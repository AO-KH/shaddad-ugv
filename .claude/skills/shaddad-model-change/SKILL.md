# Shaddad model change on request

The Shaddad models are generated by the builders in scripts/build:
- the 125 files under models/ and subsystems/;
- the benches tests/<domain>/tb_*.slx.

`build_all` lists the builders in build order. A change made only in a model is lost at the next rebuild. So every change goes into a builder, and the model is then rebuilt from it. Use `model_edit` only to try something out in the user's session, never as the change itself.

The MATLAB work runs where the shaddad-test-fix skill says:
- short work in the user's shared MATLAB, with the same manners;
- long builds and runs in a batch MATLAB, through `bash tools/agentic/run_batch.sh`.

**Parameter changes need no rebuild.** The models read `P` (from `params/*.m`) when they compile. A batch MATLAB builds a fresh `P` at start; the user's session keeps the old `P` until the user restarts the project, and you must not overwrite it there.

**Who does what with the agent team** (`tools/agentic/README.md`):
- the owning subsystem engineer makes the change;
- `shaddad-integration` checks the top level when a change crosses subsystems;
- `shaddad-docs-keeper` updates the ICD, spec, decisions and STATUS;
- `shaddad-tester` runs the tests;
- `shaddad-reviewer` checks the result before it is kept.

## Steps

0. **Look for earlier work on the same change:**
   - the dashboard (`tools/dashboard/notes.json` and `journal.jsonl`);
   - the open problems in `docs/STATUS.md`;
   - the ledgers under `.superpowers/sdd/`;
   - the notes and transcripts of earlier sessions (`search_session_transcripts`).

   A change may already have an analysis, an exact edit list and the user's approval. Line numbers in old notes drift, so find each spot by its text.
1. **Restate** the change in a sentence or two: the models, blocks and signals it touches, and what will behave differently.
   - Ask only about what would change the result, such as which bus a new signal rides on, a value, or a limit.
2. **Inspect** in the user's shared MATLAB:
   - `model_overview` of the model;
   - `model_read`, `model_query_params` and `model_resolve_params` around the change.

   Then read what constrains it:
   - docs/icd.md, for the buses and signals;
   - docs/specs/<domain>.md;
   - the decisions (D1 to D65 and any newer) in docs/architecture.md (its section 2b overrides the specs).
3. **Find the builder.**
   - Run `build_all('All', 'DryRun', true)` and `grep -rn "<block, signal or model name>" scripts/build`.
   - Read the part of the builder that makes the area, and follow its helpers: `shaddad_bu` adds blocks, lines and ports, and saves with the positions kept.
4. **Ask first when the change ripples.** That means a change to:
   - a Bus object or an ICD row;
   - a Model Reference interface;
   - a parameter in P (P stays purely numeric, D58);
   - several models;
   - a test's expected values.

   Say what else must change with it: other builders, docs/icd_static_sections.md, tests.
5. **Edit the builder** in its own style:
   - names: picks are `<port>_<element>`, and lines are named;
   - layout: the builder sets the positions, and shaddad_bu routes the lines;
   - each file's line endings.
6. **Rebuild** only the builders involved, dependencies first and benches last.
   - Before rebuilding in the user's session, check `bdIsDirty` on the models the build rewrites.
   - Send long builds to a batch MATLAB.
   - Never run `build_shaddad_mcu('all')` or `build_shaddad_mcu()`. Never run `build_fw_platform` without unit names.
7. **Check:**
   - the "Checks after a builder change" of the shaddad-test-fix skill: layout, interfaces, t_layout;
   - a compile: `set_param('<model>', 'SimulationCommand', 'update')`, then `model_read_diagnostics`;
   - `Simulink.BlockDiagram.getAlgebraicLoops('Shaddad_System')` when the top level changed;
   - the domain's tests, through the shaddad-test-fix loop.
8. **Docs.**
   - An interface or structure change goes into docs/icd_static_sections.md; then `shaddad_icd_report()` regenerates docs/icd.md.
   - A top-level change also updates the model map in docs/STATUS.md.
   - Never edit docs/report/**.
9. **Report:**
   - a picture before and after the change: `print('-s<model or subsystem>', '-dpng', '-r100', 'work/agentic/<name>_before.png')`;
   - the builder lines changed;
   - the check results;
   - what is left.

   Log it: `python tools/dashboard/log.py done "<text>" --task "Model change"`.
