# RC Row Test Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `phase1_row_test` asks rows / minutes / ambient / sprayer / fast, runs an unattended RC row-driving
session of the real-robot model in a background MATLAB with a simulated driver, and saves every plot page, a
field page and a summary.

**Architecture:** A pure MATLAB driver step function (`row_driver_step`, codegen-safe, explicit state) moves the
operator sticks; it is tested first on a MATLAB kinematic bench, then placed as choice 4 of the
`Operator_Console` variant in `Shaddad_System`, fed the delayed true pose and MCU mode. Scenario `R1` sets the
field world, temperatures, fidelity and stop time; a background worker runs it and writes the plots and summary.

**Tech Stack:** MATLAB R2026b, Simulink, Simscape; matlab.unittest; project build scripts (`scripts/build`).

**Spec:** `docs/superpowers/specs/2026-10-27-rc-row-test-design.md`

## Global Constraints

- Models are generated by the build scripts, never edited by hand. Never run `build_shaddad_mcu('all')` or `build_shaddad_mcu()`; the MCU does not change.
- P stays numeric (D58): every new parameter is a number or numeric array; MATLAB Function blocks get sub-structs only.
- No version control: before a task edits an existing file, copy it to `work/backup/rowtest_<yyyymmdd>/` (once per file).
- Phase B (Tasks 7-11) edits shared files and rebuilds `Shaddad_System`: start it only after the report session (local_91ab6f01) has finished its second Full suite and delivered report v1.1. Phase A (Tasks 1-6) writes new files only.
- The driver acts only through `Bus_OperatorCmd` (the RC chain); it never writes MCU or plant signals.
- Same inputs give the same run: no unseeded randomness (the steering wobble is a sum of sines).
- No 3-D animation: `VC_VIZ = 0`. Fidelity: full detail by default; `Fast` = `P.sim.endurance` `VC_PACK`, `VC_DRIVE_FID`, `VC_STRUCT_FID`.
- Interruptions: drive on through derates; when the MCU leaves MANUAL (CTRL_STOP 7, ESTOP 8, FAULT 9, or STANDBY 2 not caused by the driver) for 0.5 s, sticks neutral, run ends; no automatic reset.
- English only. The user manual is not changed (usage goes to `docs/row_test.md`).

## Review Focus

- Minutes longer than the battery lasts: Sim_Monitors stops at the SoC floor (`P.sim.stop_soc`); the summary must say "battery at the SoC floor", not "time up" (test in Task 4).
- Hot runs (50-55 degC): a BMS trip drops the MCU out of MANUAL; the driver ends the run and the summary names the BMS fault word (tests in Tasks 3 and 4).
- The background MATLAB fails (compile error, licence): the run folder must still get `summary.txt` with the error and `done.txt` (test in Task 6).
- A second row test started while one runs: refuse with a message naming the running folder unless `'Force', true` (test in Task 6).
- An odd number of rows: the second pass enters row 1 from the far end and still counts rows correctly (test in Task 3).

### Task 3: Driver state machine and kinematic bench

**Files:**
- Create: `utilities/row_driver_init.m`, `utilities/row_driver_step.m`, `tests/rc/row_driver_bench.m`
- Test: `tests/rc/t_row_driver.m`

**Interfaces:**
- Consumes: `row_test_prm` (prm).
- Produces: `s = row_driver_init(prm)` (struct; `s.phase` double) and
  `[op, s, ended] = row_driver_step(s, pose, v, mcu_mode, prm)`; `pose = [x y psi]`, `v` forward speed,
  `mcu_mode` ShaddadMode code as double; `op` has the fields and order of `P.scen.dash` (Bus_OperatorCmd);
  `ended` 0/1. Both `%#codegen`, no persistent variables (the MATLAB Function block keeps `s`).
  Phase codes: `0 START, 1 ARMING, 2 ROW, 3 TURN, 4 RETURN, 5 STOP, 6 DISARM, 7 ENDED, 8 ABORT`.
- Produces: `B = row_driver_bench(prm, T, opt)` in `tests/rc`: MATLAB loop at `prm.Ts`; vehicle = unicycle with
  first-order lags (tau 0.3 s speed, 0.15 s yaw rate); sticks -> (v, w) by `interp1` of the prm tables, yaw rate x
  `opt.slip` (default 0.9, emulates turn slip); MCU model: STANDBY 2 until armed with neutral sticks, then
  MANUAL 3; disarm -> 2; `opt.fault_at` (s) forces 9. Returns `B.t, B.pose (n x 3), B.v, B.phase, B.thr,
  B.steer, B.arm, B.impl, B.tx, B.ended_t`.

Behaviour to implement (spec section 7): transmitter on at `t_tx`, neutral sticks, `sw_mode 1`; `sw_arm 1` at
`t_arm`; drive only after MANUAL (abort after `t_arm_wait` without it); serpentine rows at `v_row`, slow to
`v_turn` within `d_slow` of the row end; U-turn radius `spacing/2` into the next row; after row N, RETURN along
the headland lane `x_e + dir*headland/2` to row 1, enter it with the opposite direction, next pass; pure-pursuit
steering with look-ahead `L_look` on the current line / arc / lane, plus wobble
`wobble*(sin(2*pi*f1*t) + sin(2*pi*f2*t + 1))/2`; sticks rate-limited to `dx_max` per step; pose delayed by
`n_delay` samples (ring buffer in `s`); `sw_impl 2` in ROW when `sprayer`, else 1; at `t_drive` after MANUAL:
STOP (neutral) until `v < 0.05` for `t_end_hold`, DISARM (`sw_arm 0`) for `t_disarm`, ENDED (`ended = 1`);
mode not MANUAL for `t_abort` while driving: ABORT (neutral), ENDED 3 s later.
