## 0. Common rules for every task

1. **Shared MATLAB R2026b session.** Never run `cd`, `clear all` / `clearvars` in base,
   `close all`, `bdclose all`, `restoredefaultpath` or `rmpath`. Close only models you opened
   (`close_system(m,0)`). Never save library files. Keep each MATLAB call under a few minutes.
   **Every variable you create in the base workspace carries your task prefix (`tmp_<task>_*`),
   including loop indices and `catch` variables; clear only your own prefix.** (Superseded for the team by the
   work rules of 2026-11-16, `tools/team/AGENT_RULES.md`: nothing is assigned in the shared base workspace; D62 is
   marked so.)
2. **Data.** Start with `shaddad_params(...)` (options `'World'`, `'Implement'`, `'Phase'`, `'Target'`).
   Every numeric value in a block comes from `P.<domain>` / `Ts` (block parameter expressions such
   as `'P.drive.esc.Kp_w'`). Missing parameters go into **your own** `params/param_<domain>.m`
   (numeric/logical only, SI; strings only in `P_meta`). MATLAB Function blocks get **sub-structs**
   as non-tunable parameters (e.g. `P.gnc.fsm`), never the whole `P` (8 MB). Bus objects come only from
   `buses/buses_<domain>.m`; if you need a bus change, edit only your domain's bus file, rerun
   `shaddad_buses('check')` and `shaddad_icd_report`, and list the change in your report.
3. **Programmatic build.** Every `.slx` is generated by an idempotent function
   `scripts/build/build_<name>.m`: close the model if open, delete and recreate with
   `new_system` (`'Subsystem'` for Subsystem Reference files), `add_block`, `add_line`,
   `set_param`, then `shaddad_bu('save', name, file)`: it lays out every level of the file with
   `shaddad_layout` (model layout spec 6 and 7: blocks placed, lines re-added and named, wiring asserted;
   an engine error stops the save) and saves it to the exact path. Never hand-edit a model, and never
   set line points. Block names that contain a newline need `sprintf('...\n...')`. Rebuild with
   `build_all` (`'NoMCU'` by default, `'MCU'` or `'All'`) in a batch MATLAB (`matlab -batch`): it runs
   the builders dependencies first and closes every loaded model without saving;
   `build_all(scope, 'DryRun', true)` only lists the calls. It leaves out `build_shaddad_battery`,
   `build_stubs`, `build_project` and `build_targets` (see its help).

   **Picks and bus element ports** (model layout spec 6.2, 6.3 and 13). A block takes each signal it
   needs from a bus right in front of its input (a pick): an In Bus Element block showing
   `port.element` (`shaddad_bu('pick')`) in inner subsystems and inner Subsystem Reference files, a Bus
   Selector per consumer at the root of Model files and ICD-listed files, whose root ports stay classic
   Inport and Outport blocks with explicit types and rates (rule 5). Three or more signals from one block
   to one block travel as one virtual bus (`shaddad_bu('vbus')`, or an Out Bus Element port,
   `shaddad_bu('outbus')`). Create the first block of a bus element port from the library and set its
   `PortName`; create every further block of that port by copying it (`add_block(existingBlock,
   newPath)`) and set its `Element`, because a second library block with the same `PortName` fails. A
   bus element block's name must differ from its port's name, and a bus-object typed In Bus Element port
   cannot carry a sample time.
4. **Blocks first.** Use the library blocks named in your task (paths verified in R2026b or in
   your spec). A MATLAB Function block only where the task lists it (exceptions: D70), with its body in a
   `%#codegen` `.m` file on the project path called in one line. **Stateflow is not installed:**
   no `sflib/Chart`; state machines are MATLAB Function FSMs using the enum classes in `buses/`.
5. **Ports.** Root ports exactly as `docs/icd.md` section 3 (names, order, `Bus: Bus_<Name>`
   data types, explicit non-constant `SampleTime`; nonvirtual buses at Model-block boundaries, Inport
   `BusOutputAsStruct = 'on'`). Task T01 creates a stub of every file; you replace the stub of
   your files and must keep its ports (`utilities/shaddad_check_interfaces` must report 0).
6. **Simscape.** No Solver Configuration inside domain files (test benches add one: local
   `NE_BACKWARD_EULER_ADVANCER`, 1 ms, `DoFixedCost = 'on'`). Connection Ports with explicit
   `ConnectionType` (`'Connection: foundation.electrical.electrical'`,
   `'Connection: foundation.mechanical.rotational.rotational'`, `'Connection: foundation.thermal.thermal'`).
   Thermal ports may connect child SSRs only inside one domain top SSR (ICD 1). Variant Subsystems that
   contain Simscape blocks use `VariantActivationTime = 'update diagram'`, identical ports in every choice,
   and keep every node in the DC48 network: a choice without a motor carries the **network tie** of
   ICD 2 (D35).
7. **Rates.** Port / task rates only {0.001, 0.005, 0.01, 0.05, 0.1, 0.2, 1} s; 0.014 / 0.007 only inside
   `RC_Link_Sim`. Explicit Rate Transition blocks (`Integrity = 'on'`, `Deterministic = 'on'`) between
   rates with an **integer ratio** (chain through 0.001 otherwise). Compiled rates must be a subset of
   `P.sim.Ts_compiled_allowed`.
8. **No algebraic loops, explicit breakers.** Every Simulink path that leaves a Simscape network
   (PS-Simulink) and returns to it (Simulink-PS) at the same rate contains one Unit Delay at that rate
   (D36). Benches and T01 run `Simulink.BlockDiagram.getAlgebraicLoops` and report 0.
9. **Conventions.** ENU / FLU, yaw from East CCW, pitch + = nose down, physical specific force,
   uT, K, discharge-positive current, forward-positive track quantities (ICD section 1).
10. **Tests.** `matlab.unittest` class `tests/<domain>/t_<name>.m` (`runtests` must pass), benches
    `tests/<domain>/tb_<name>.slx` built by a script. Report a table of measured numbers vs criteria.
11. **Code generation is BLOCKED, not failed, while Simulink Coder is not installed (D31).** Every
    "generates code" item first checks `any(strcmp({ver().Name},'Simulink Coder'))`; if false, the test
    is marked `assumeTrue` (Incomplete) with the message `BLOCKED: Simulink Coder not installed`. Early
    codegen checks use `cs_GenARM` (ert, generic ARM Cortex-M7, `GenCodeOnly`); STM32 board builds are T17.
    (Resolved by D121, 2026-11-23: Simulink Coder has been installed since 2026-11-07, so the check passes and the
    codegen items run; the STM32 board builds of T17 still wait on the STM32 tools, card B-00.)
12. **Ownership.** Do not edit files owned by another task; report interface problems instead.
